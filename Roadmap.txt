تفكيرك المعماري (Architectural Thinking) ممتاز جداً! الانتقال من مرحلة "كود تجريبي" إلى "هندسة تطبيق قابل للتوسع" (Scalable Application) هو الخطوة الأهم لنجاح أي مشروع تقني.

تأجيل ميزة "تتبع وتزامن التلاوة" (Audio/Voice Sync) للإصدار الثاني (V2) هو قرار ذكي جداً لتقليل الـ Time-to-Market والتركيز على الميزة التنافسية الأساسية (التجويد التفاعلي وتصفيته).

إليك مقترح متكامل لبنية البرنامج، هيكل البيانات، وخطوات التنفيذ ليكون البرنامج قابلاً للتوسع مستقبلاً:

### أولاً: البنية التحتية للبرنامج (System Architecture)

لضمان عدم وجود بيانات ثابتة (Hardcoded) في الكود، سنقسم البنية إلى 3 طبقات رئيسية:

1. **طبقة العرض والواجهة (Frontend Layer):**
* كود HTML/CSS/JS مبني بشكل تركيبي (Modular).
* يُفضل استخدام إطار عمل خفيف مثل Vue.js أو React، أو حتى Vanilla JS (جافاسكريبت نقي) مع بنية مكونات (Components)، بحيث يكون هناك مكون خاص بـ "رسم الصفحة"، وآخر لـ "اللوحة الجانبية"، وثالث لـ "الفلاتر".


2. **طبقة جلب بيانات المصحف العثماني (Quran Data Layer):**
* سنعتمد على واجهة برمجة تطبيقات (API) الخاصة بـ Quran.com (الإصدار الرابع V4).
* ستجلب هذه الطبقة الكلمات، أرقام الصفحات، أرقام السطور، ومواضع الكلمات لضمان التطابق التام مع المصحف المطبوع.


3. **طبقة بيانات التجويد المخصصة (Custom Tajweed Layer):**
* ملفات `JSON` خارجية خاصة بمشروعك (مستضافة على سيرفر أو GitHub).
* لن نكرر فيها النص القرآني، بل سنربط الحكم التجويدي بـ **"مُعرّف الكلمة" (Word ID)** أو (رقم السورة:رقم الآية:رقم الكلمة).



---

### ثانياً: تصميم قاعدة بيانات التجويد (JSON Schema) وتوحيد الألوان

الألوان القياسية المتعارف عليها في المصحف المجود (مثل طبعة دار المعرفة) هي:

* **الأحمر (بتدرجاته):** للمدود (أحمر غامق 6 حركات، أحمر فاتح 4 حركات).
* **الأخضر:** للغنة (الإخفاء، الإدغام بغنة، الإقلاب).
* **الأزرق (الغامق والفاتح):** للقلقلة، وتفخيم الراء.
* **الرمادي:** للحروف التي تُكتب ولا تُنطق (الإدغام بغير غنة، اللام الشمسية).

**هيكل ملف الـ JSON المُقترح (مثال قابل للتوسع):**

```json
{
  "surah_1": {
    "1:1:1": { 
      "word_text": "بِسۡمِ",
      "rules": [
        {
          "type": "tarqeeq",
          "color_code": "none",
          "target_letters": "ب، س، م",
          "description": "ترقيق الحروف."
        }
      ]
    },
    "1:1:3": {
      "word_text": "ٱلرَّحۡمَٰنِ",
      "rules": [
        {
          "type": "lam_shamsiya",
          "color_code": "#808080", 
          "target_letters": "ل",
          "description": "لام شمسية مدغمة (لا تُنطق)."
        },
        {
          "type": "madd_tabiee",
          "color_code": "#FF0000",
          "target_letters": "ا",
          "description": "مد طبيعي حركتان."
        }
      ]
    }
  }
}

```

*ملاحظة: استخدام مفتاح مثل `"1:1:3"` (سورة 1 : آية 1 : كلمة 3) يجعل قاعدة البيانات خفيفة جداً وسريعة في البحث، ويسهل دمجها مع بيانات Quran.com.*

### ثالثاً: تهيئة البرنامج لقابلية التوسع (Scalability)

للتأكد من أن البرنامج قادر على استيعاب "تتبع التلاوة" وغيرها في المستقبل دون إعادة كتابة الكود:

1. **فصل منطق الصوت (Audio Module Isolation):**
* سنقوم ببناء كود الصوت في ملف منفصل (مثلاً `audioManager.js`). في الإصدار الأول سيكون هذا الملف فارغاً أو يحتوي على مشغل بسيط جداً، وفي الإصدار الثاني سنطوره ليحتوي على التزامن المعقد دون المساس بملفات الواجهة أو الرسم القرآني.


2. **استخدام نمط الأحداث (Event-Driven Architecture):**
* الكود سيعتمد على "الأحداث". مثلاً: `onWordClick` و `onFilterChange`.
* مستقبلاً، عند إضافة التتبع الصوتي، كل ما سنفعله هو إطلاق حدث `onAudioWordChange` لتظليل الكلمة، وستقوم واجهة المستخدم بالتفاعل معه تلقائياً.


3. **التصميم المتجاوب للبيانات (Lazy Loading):**
* لن نقوم بتحميل بيانات التجويد للقرآن كاملاً في نفس اللحظة (حجم الملف سيكون ضخماً). البرنامج سيقوم بتحميل ملف الـ JSON الخاص بـ "السورة الحالية" أو "الصفحة الحالية" فقط بناءً على ما يعرضه المستخدم.



---

### رابعاً: خطة العمل وخطوات التنفيذ (Roadmap)

**المرحلة الأولى (V1.0 - الأساس والتجويد التفاعلي):**

1. **تصميم واجهة المستخدم (UI Engine):** كتابة الدالة التي تستدعي نص الصفحة من `Quran.com API` وتضع كل كلمة في السطر الصحيح (Line Break) لتبدو كالمصحف تماماً.
2. **تطوير محرك التجويد (Tajweed Engine):** كتابة الكود الذي يقرأ ملف الـ JSON الخاص بك، ويقوم بـ:
* تلوين الحروف (بناءً على الألوان القياسية).
* إظهار تفاصيل الحكم في "اللوحة الجانبية" عند الضغط على الكلمة.


3. **تطبيق الفلاتر (Filters):** تشغيل أزرار التصفية في الأعلى لعرض أحكام معينة فقط وتخفيت (Dim) الباقي.

**المرحلة الثانية (V1.5 - إعداد البيانات):**

1. بناء ملفات الـ JSON لسورة الفاتحة وقصار السور لاختبار جودة عرض الأحكام.
2. مراجعة دقة الألوان وتطابقها مع المصحف المجود.

**المرحلة الثالثة (V2.0 - مستقبلاً - محرك الصوتيات):**

1. دمج ملفات الصوت لكل قارئ.
2. ربط التوقيتات (Timestamps) لتظليل الكلمات أثناء التلاوة.
3. (اختياري) دمج تقنيات التعرف على الصوت (Speech Recognition) للمزامنة الحية.

هل هذا التصور الهيكلي يتوافق مع رؤيتك؟ إذا كانت الإجابة نعم، هل ترغب في أن نبدأ ببرمجة **أول جزء وهو: كود قراءة وبناء شكل صفحة المصحف من API (بدون الكلمات الصلبة في الكود)** لنرى كيف ستبدو الأسطر وتتطابق مع المصحف العثماني؟
